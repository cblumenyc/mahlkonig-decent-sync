# Mahlkönig - Decent sync for Classic

Community integration for one Decent and one Mahlkönig E64 WS. The local server is required. This plugin never starts extraction.

Install the complete Classic ZIP from the same release as the server, with de1app closed. The folder and namespace are `mahlkonig_decent_sync`. Existing `decent_sync` installations require the assisted migration described in the installation guide; do not enable both names.

In settings, enter the server's LAN address and choose **Save & connect**. The plugin pairs with that installation's identity. Saved events stay bound to that server. New installations default to **Scale only**; existing approved measurement preferences survive migration. Complete profile commissioning and target verification in the server dashboard before enabling feedback.

**Scale + backup** uses the Classic native volume stop if the scale becomes unavailable, with the estimate and fallback reason recorded. Volume estimates are uncalibrated. **Banners** controls placement, duration and a local preview. **Auto / Light / Dark** controls appearance. The status indicator requires readiness as well as connectivity. The Streamline Grind readout is the measured burr position and remains read-only.

**Updates** checks the paired server for its complete matching package. Installation requires both devices idle and an empty outbox. All declared files, hashes, sizes, versions and loader compatibility are checked. A verified generation is selected atomically; the current capture hooks run until you fully close and reopen de1app. No downloaded code is evaluated during installation. Settings, queued bytes and shot history live outside the replaced code. Interrupted staging leaves the previous generation selected. The `previous-generation` pointer identifies the rollback generation; use the documented recovery procedure with de1app closed.

Start extraction on the Decent. A physical grinder press arms feedback within the original pending window. Missing cycle identity or incomplete measurements produce history-only records. A server acknowledgement confirms durable storage; native receipt, changed targets and physical burr movement remain separate outcomes.
